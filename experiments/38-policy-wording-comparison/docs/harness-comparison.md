# Which harness to use

Both harnesses call `compare()` in `src/compare.py` and stop. Neither interprets favourability, recommends buy, sell, or renew, drafts an endorsement, contacts a broker, or writes a policy administration system. The same manifest, the same tool schema, and the same tests back both.

The GitHub Copilot harness is a Copilot Studio authoring and orchestration framework. It is not the GitHub Copilot service. That sentence is on the harness overview opened on 6 November 2026. The page says customer data is not sent to or processed by the GitHub Copilot service when agents run in Copilot Studio.

## What was opened

On 6 November 2026 the harness overview named three harnesses: GitHub Copilot, Customer Conversation, and standard. It did not mark the GitHub Copilot harness as preview. It says agents and workflows on that harness use Copilot Credits. The billing page linked from the table was not opened. No price is copied here.

The generative-orchestration guidance opened the same day says the planner can invoke a topic by trigger phrases and when its described purpose matches the need, and that tool names carry more weight than descriptions. It does not describe numeric routing weights. These skills do not list trigger phrases and do not assign routing weights. Whether that planner is the selector for the GitHub Copilot harness was not stated on the harness overview. That link is unverified.

## When the standard harness fits

Use the standard harness when the specialist pastes one pack, wants the JSON back, and stops. One topic. No multi-step explanation. See [copilot-studio/README.md](../copilot-studio/README.md). This is a build guide, not an importable solution.

## When the GitHub Copilot harness fits

Use the GitHub Copilot harness when the specialist wants the comparison walked through in steps: the full comparison, then the material-difference list, then one row restated with its citations. The skills are in [skills/](../skills/). They tell the agent to call the Python and to stop. They do not tell it to rank a wording.

The overview says this harness supports skills, memory, and file creation inside a sandbox. This experiment does not ask it to create a Word or PDF endorsement. An administrator control to turn memory off was not on the page. The skills say not to store the wordings.

## What neither harness is

The Customer Conversation harness is described on the same overview for customer voice and chat. It is not built here. A policy wording does not belong on a public chat.

Microsoft Foundry is a catalogue option. It is not called. See [foundry.md](foundry.md).
